# HHL-03 — Telemetry and Detection

## Objective

Analyze structured security telemetry generated by a synthetic campaign.

## Run

```bash
docker compose -f infra/docker-compose.yml up -d --build
curl -X POST http://127.0.0.1:8090/campaigns/HHL02-A/send
```

Open MailHog and follow one training link. Then inspect:

```bash
curl http://127.0.0.1:8090/campaigns/HHL02-A/events
```

## Tasks

1. Identify the `run_id` / correlation ID.
2. Trace a `delivered` event to its corresponding `clicked` event.
3. Explain which fields are useful for SIEM correlation.
4. Identify fields that must never contain credentials or message bodies.
5. Propose one detection rule for suspicious click activity.

## Expected telemetry

```text
event_id
campaign_id
user_id
event_type
timestamp
correlation_id
source
metadata
```

Training tokens are not exposed through the telemetry API and are stored only as hashes.

## Evidence

Submit one sanitized event sequence, one detection hypothesis, one mitigation and one telemetry limitation.

## Safety

All events belong to synthetic identities and the local lab.
